## 总目标

把小原圈的用户身份、注册登录、卖家认证、个人资料、商家秀、礼物系统和全局滚动公告整理成更清晰的买家/卖家分层体验：

- 新用户先登录/注册，再进入平台。
- 注册后默认是最低级的普通买家/游客模式，不能直接发布上新。
- 只有通过卖家认证后，才在「我的」页面显示发布/上新入口。
- 用户资料、性别、头像、ID 修改入口要清晰独立。
- 「我的」页面去重视频认证，统一改成卖家认证入口。
- 检查并完善礼物系统，尽量向抖音礼物标识/动效体验靠近。
- 商家秀继续优化展示效果、图标和认证商家卡片。
- 将原社区顶部置顶通告栏升级为全局可见的礼物/公告滚动条，所有主要页面都可以看到。
- 开发/演示环境可加入模拟商品、模拟卖家、社区帖子和 IM 对话，让页面效果更完整。
- 首页产品自动轮动要遵循“手动优先”：用户手动翻动时暂停自动轮动，无手动时默认自动向上刷新。
- 所有需要图片的展示位，可使用 iMega2 生成或自制配套插图，保证页面有完整视觉效果。
- 宝贝分类图标需要更贴合女性用品：上衣改胸罩标识，下衣改女生小内裤图标，套装改比基尼图标。

## 一、登录/注册与新用户默认身份

### 需求描述

新用户打开网站时，应该优先看到登录页面；没有登录时不能直接进入首页浏览完整内容。

注册完成后，用户默认进入最低级身份：

- 普通买家
- 游客/买家模式
- 不具备卖家发布能力
- 不显示上新/发布入口

### 预期体验

1. 未登录用户打开网站：
   - 进入登录页。
   - 可切换注册。

2. 用户注册成功后：
   - 自动登录或跳转登录后进入平台。
   - 默认身份是买家/游客模式。
   - 可以浏览、购买、互动。
   - 不能发布商品。

3. 未认证卖家时：
   - 「我的」页面不显示「发布上新」入口。
   - 可看到「申请卖家认证」入口。

4. 通过卖家认证后：
   - 「我的」页面显示发布/上新入口。
   - 才允许进入发布商品流程。

### 可能涉及文件

前端：
- `frontend/src/pages/auth/login/index.vue`
- `frontend/src/pages/tabbar/me/index.vue`
- `frontend/src/pages/tabbar/publish/index.vue`
- `frontend/src/pages/product/publish/index.vue`（如果后续拆出非 tab 发布页）
- `frontend/src/store/modules/user.ts`
- `frontend/src/api/modules/auth.ts`
- `frontend/src/api/modules/user.ts`
- `frontend/src/pages.json`
- `frontend/pages.json`

后端可能涉及：
- 用户注册接口
- 当前用户资料接口
- 用户身份/卖家认证状态字段
- 发布商品接口权限校验

### 整改原则

- 前端隐藏入口只是体验层，后端发布商品接口也必须校验卖家认证状态。
- 不要只靠本地状态判断卖家身份，要以服务端用户资料/认证状态为准。
- 默认用户不能被前端伪造成卖家。

## 七、全局礼物/公告滚动栏

### 需求描述

原来规划在社区置顶处增加礼物滚动信息；现在调整为全局页面都可以看到的滚动栏。

全局滚动栏用于展示：

- 最新礼物动态，例如：用户 A 送给用户 B 一个玫瑰。
- 平台公告，例如：认证提醒、活动通知、交易安全提醒。
- 重要动态优先覆盖旧信息，新消息可轮询展示。

### 预期体验

1. 不只出现在社区页，而是在主要前台页面全局可见。
2. 位置建议在页面顶部安全区域下方，或全局 App 容器中固定显示，不遮挡 tabbar 和主要操作按钮。
3. 礼物动态来自真实礼物记录，不造假用户、不造假礼物。
4. 公告来自后端公告配置或已有通知接口，不写死长期假数据。
5. 有新礼物时优先展示新礼物；没有礼物时可以展示公告。
6. 如果礼物和公告都没有，则自动隐藏，不占页面空间。
7. 所有页面显示风格统一，避免每个页面单独写一套通告栏。

### 可能涉及文件

前端：
- `frontend/src/App.vue`（全局挂载位置候选）
- `frontend/src/components/GlobalTicker.vue`（建议新增全局滚动栏组件）
- `frontend/src/api/modules/gift.ts`
- `frontend/src/api/modules/notification.ts` 或新增公告接口模块
- `frontend/src/pages/tabbar/message/index.vue`（移除社区内重复置顶通告栏，避免重复显示）
- 需要检查所有 tab 页面顶部间距：
  - `frontend/src/pages/tabbar/home/index.vue`
  - `frontend/src/pages/tabbar/category/index.vue`
  - `frontend/src/pages/tabbar/publish/index.vue`
  - `frontend/src/pages/tabbar/message/index.vue`
  - `frontend/src/pages/tabbar/me/index.vue`

后端：
- 最近礼物动态接口，例如：`GET /api/gifts/recent` 或已有接口扩展
- 公告列表接口，例如：`GET /api/announcements/active`，也可以先复用通知接口
- 礼物记录查询 SQL
- 公告启用/过期时间/排序字段

### UI 建议

全局滚动栏做成轻量、小而美的玻璃质感胶囊条：

- 左侧动态图标：礼物用礼物图标，公告用喇叭/铃铛图标。
- 中间单行滚动文案，文字不要太多。
- 右侧轻微流光/小箭头，不做大面积遮挡。
- 高度控制在 56rpx 左右，所有页面统一。
- 不要加解释说明小字。
- 和商家秀、社区、首页的暖色系保持一致。

### 动效建议

第一阶段：

- 横向/纵向单行滚动。
- 新消息淡入替换。
- 礼物图标轻微闪光。
- 点击礼物动态可进入收礼用户主页或礼物页；点击公告可进入公告详情或通知页。

第二阶段：

- 大额礼物触发短暂浮层。
- 全屏礼物特效。
- 礼物连击效果。
- WebSocket/SSE 实时推送，减少轮询延迟。

### 验收标准

- 首页、宝贝、商家秀、社区、我的等主要页面都能看到同一套全局滚动栏。
- 社区页不再单独重复一条置顶礼物栏。
- 礼物动态使用真实后端礼物记录。
- 无数据时隐藏，不显示假用户假礼物。
- 不遮挡页面主操作按钮、发布按钮、tabbar。

## 十一、首页产品自动轮动与手动优先规则

### 需求描述

首页产品列表已有自动向上轮动/刷新展示需求。需要补充交互规则：当用户手动翻动、滑动、拖动产品列表时，必须以用户手动操作为准；如果用户没有手动翻动，则系统默认自动向上刷新/轮动。

### 预期体验

1. 默认状态：
   - 首页产品区域自动向上轮动。
   - 轮动节奏平稳，不要太快。
   - 产品展示保持真实数据，不造假库存。

2. 用户手动操作时：
   - 用户向上/向下滑动产品列表，立即暂停自动轮动。
   - 手动翻动的位置优先，不要被自动滚动抢回去。
   - 用户正在触摸/拖动时，自动轮动不得继续推进。

3. 手动操作结束后：
   - 可以延迟一段时间再恢复自动轮动，例如 5-10 秒。
   - 如果用户继续手动滑动，则重新计时。
   - 恢复自动轮动时从用户当前停留位置继续，而不是突然跳回顶部。

4. 无手动操作时：
   - 默认继续自动向上刷新/轮动。
   - 到底部后平滑循环或刷新下一批真实商品。

### 可能涉及文件

前端：
- `frontend/src/pages/tabbar/home/index.vue`
- 可能涉及首页产品滚动组件，如后续拆分：`frontend/src/components/HomeProductTicker.vue`
- `frontend/src/api/modules/product.ts`

### 技术建议

- 使用 `touchstart` / `touchmove` / `touchend` 或 scroll 事件判断用户手动操作。
- 用 `isUserInteracting` 控制自动轮动暂停。
- 用 `lastManualScrollAt` 记录最后一次手动操作时间。
- 自动轮动恢复前检查：`Date.now() - lastManualScrollAt > 5000`。
- 如果使用 CSS animation，需要在用户触摸时暂停 animation-play-state。
- 如果使用 JS 定时滚动，需要在触摸/滚动时 clear timer 或跳过 tick。
- 如果产品不足以滚动，不要强行动画；可以静态展示。

### 验收标准

- 用户不操作时，首页产品默认自动向上轮动。
- 用户手动滑动时，自动轮动立即暂停。
- 用户手动停留位置不会被自动刷新抢走。
- 用户停止操作一段时间后，自动轮动从当前位置恢复。
- 产品数据仍来自真实商品接口；如需演示填充，只能重复真实记录或启用明确 demo/mock 模式。
